# Tenchage-ppt v2.1 技能指南

> 哈哥 (利铭) 专属 · 腾讯智慧零售与生活产业路演风格
> v1.0（纯 2x2 卡片）→ v2.0（7 种专业布局 + QA 流程）→ v2.1（新增 circle_loop 环形闭环模板）

**字体铁律：标题/关键字用`腾讯体 W7`，正文/其他用`腾讯体 W3`（中文名），禁止斜体，禁止其他字体。**

**⛔ 英文装饰字铁律（哈哥 2026-04-20 明确约定）**：
- **所有模板一律禁止**使用 `PHASE 01` / `CLOSED LOOP` / `CORE VALUE` / `STEP 01` / `KEY VALUE` 等英文装饰字（无论颜色深浅）。
- 卡片编号、中央飞轮、步骤标识都必须用**纯中文或阿拉伯数字**表达。
- 以后新增任何布局模板，都必须遵守此规则。

**⛔ 顶部蓝绿装饰线铁律**：页面顶部不再绘制蓝色+绿色装饰小横条，主标题直接从 y=0.35 起始。

## 一、视觉基因（所有布局共享）

### 1.1 幻灯片基础
```
尺寸：LAYOUT_16x9（10" × 5.625"）
背景：纯白 #FFFFFF
左边距 M = 0.5"
内容区宽 CW = 9.0"
```

### 1.2 顶部装饰线（每页必须有）
```
蓝色段：x=0.5, y=0.3, w=1.0, h=0.08, fill=#1A50D6 (腾讯蓝)
绿色段：x=1.5, y=0.3, w=0.8, h=0.08, fill=#00A45D (腾讯绿)
```

### 1.3 主标题（每页必须有）
```
x=0.5, y=0.6, w=8, h=0.4
24pt 粗体 #1D2129（禁止斜体）
```

### 1.4 副标题（可选）
```
x=0.5, y=1.2, w=8, h=0.3
12pt 粗体 #4E5969（禁止斜体）
自动包裹为 解决"${subTitle}"
```

### 1.5 页码（每页必须有）
```
x=8.5, y=5.2, w=1, h=0.3
10pt 粗体 #4E5969 右对齐
格式：-${startPage + idx}-
```

### 1.6 配色体系
| 色值 | 名称 | 用途 |
|------|------|------|
| `1A50D6` | 腾讯蓝 | 装饰线、卡片竖条、编号、表头、强调 |
| `00A45D` | 腾讯绿 | 装饰线绿色段 |
| `1D2129` | 深黑 | 主标题、卡片标题 |
| `4E5969` | 中灰 | 副标题、正文、页码 |
| `86909C` | 浅灰 | 依赖标签、注释 |
| `E5EBF5` | 极浅蓝灰 | 卡片边框 |
| `E0E6F1` | 浅蓝灰 | 卡片阴影 |
| `EDF2FF` | 极浅蓝 | 编号圆形底、KPI 次要底 |
| `F4F5F7` | 极浅灰 | 标签底、隔行底色 |
| `FFFFFF` | 白色 | 主背景、卡片背景 |
| `C62828` | 深红 | 仅用于高风险/负面指标 |

### 1.7 禁止事项
- **禁止** 引入橙色、紫色、粉色等未列出颜色
- **禁止** 使用 3D 效果
- **禁止** 旋转中文文字（COM 导出会乱码）
- **禁止** 使用非微软雅黑字体（编号 Arial 除外）
- **禁止** 在 `addShape` 上使用渐变填充（pptxgenjs 已知 bug：`stops`/`color1+color2` 语法均导致形状不渲染），一律用**纯色填充**替代

## 二、布局类型一览

每页通过 `layout` 字段指定渲染模式，默认为 `cards`。

| layout 值 | 名称 | 适用场景 |
|-----------|------|---------|
| `cards` | 模块化卡片 | 能力/场景展示（1-8 张自适应） |
| `cards_outlined` | 描边卡片 | 步骤/模块总览（编号+标签+描边框，适合 3-6 张） |
| `summary` | 执行摘要 | 方案总纲、关键结论 |
| `table` | 比较表格 | 产品对比、功能矩阵、竞品分析 |
| `compare` | 双栏对比 | Before/After、问题 vs 方案 |
| `phases` | 三阶段流程 | 落地路径、Next Steps、时间线 |
| `kpi` | KPI 大数字 | 关键指标展示、成果数据 |
| `hierarchy` | 架构/层级 | 技术架构、组织架构、分层展示 |
| `circle_loop` | 环形闭环 | 3-5 步业务飞轮、业务闭环全景图（中央CORE+环形步骤+左右侧要点） |
| `quad_loop` | 四方闭环 | 4 步业务场景闭环（四象限大卡 + 中央飞轮 + 四方循环箭头 + 核心价值横条） |
| `trinity_pillars` | 三位一体三支柱 | 顶层方案类，三大能力柱+每柱多子卡 |
| `breakthrough_trio` | 破局三栏 | 战略拐点开篇页，橙/蓝/绿递进色 + 中段强化框 + 底部深蓝引号 banner |
| `hub_dual_cards` | 中枢双卡 | 中央飞轮/中枢 + 左右两大能力卡对比展开 |
| `hero_radial` | 放射式能力总览 | 顶层服务定位，1 大主张卡（深蓝+金色）+ 2×2 能力卡 + 底部金色陪跑条，适用"我们能做什么""腾讯提供什么" |
| `evolution_trio` | 三代进化横向流程 | 产品/能力/范式的三代演进展示，3 张独立圆角卡 + 中间箭头连接器 + 第三代橙色高亮，⚠️ 本布局破例允许橙色（`FF6A00`）作为末代高亮 |
| `split_1_2` / `split_1_4` | 1+N 分割 | 1 张大卡 + N 张小卡的分割布局 |
| `formula_phases` | 公式阶段 | 带公式符号的阶段流程 |

**渲染规则**：
- 1-3 张：单行平铺

**字段说明**：
| 字段 | 必填 | 说明 |
|------|------|------|
| `mainTitle` | ✅ | 页面主标题（24pt 粗体，禁止斜体） |
| `intro` | 可选 | 主标题下方的正文描述段。有 intro 时卡片区从 Y=1.70" 开始；无 intro 时从 Y=1.70" 开始（与 subTitle 共用空间） |
| `cards` | ✅ | 卡片数组，每张含 title / tag(可选) / desc |
| `cards[].tag` | 可选 | 标题旁的小标签文字，如"认知对齐"。渲染为**纯色蓝底**+白色文字的圆角小色块 |
| `cards[].desc` | ✅ | 字符串（换行分隔）或字符串数组。每行自动加 "·" 前缀 bullet |
| `footerBar` | 可选 | 页面底部的蓝色横条文字（适合放核心价值/总结语） |

> **⚠ pptxgenjs 限制**：`addShape` 不支持渐变填充（`stops` / `color1+color2` 均无效），标签色块统一使用**纯色填充**。
> 标签配色方案按序号轮替：前 3 张腾讯蓝 `#1A50D6`、4-5 张中蓝 `#4E82C5`、6 张浅蓝 `#7CB3E0`。

**布局自适应**：
- 3 张：单行 3 列
- 4 张：2×2
- 5-6 张：3 列 × 2 行（标准）
- 7-8 张：4 列 × 2 行

**核心尺寸参数**（以 6 张 3×2 为例）：
```
内容区宽 CW = 9.0", 左边距 M = 0.5"
列间距 colSpace = 0.25", 行间距 rowSpace = 0.25"
总内容高 maxH = 有footerBar时3.1" / 无footerBar时3.5"
列数 cols = 3, 行数 rows = 2
卡片宽 colW = (9.0 - 2*0.25) / 3 ≈ 2.83"
每行高 rowH = (maxH - rowSpace) / 2
编号标题行高 headerRowH = 0.35"
内容框高 contentH = rowH - headerRowH - 0.08"
```

**逐层渲染规则**：

#### A. intro 正文段（可选，卡片上方）
```
位置: x = M(0.5"), y = 1.15"
大小: w = CW(9.0"), h = 0.45"
字号: 10.5pt, 常规, 颜色 #4E5969
行距: 1.3 倍
有 intro 时: 卡片区 startY = 1.70"
无 intro 时: 卡片区 startY = 1.70"
```

#### B. 编号 + 标题（卡片框外上方，合并为一个文本框）
```
文本框: x = cardX, y = cardY, w = colW * 0.6, h = headerRowH(0.35")
内容: "01  共识摸底"（编号两位 + 双空格 + 标题）
字号: 13pt, 粗体, 颜色 #1D2129 (深黑)
对齐: 左对齐, 垂直底部对齐
```

#### C. 标签色块（卡片行右上角，可选）
```
形状: roundRect (圆角矩形)
位置: x = cardX + colW - tagW（右对齐）
      y = cardY + (headerRowH - tagH) / 2 + 0.04"
大小: w = min(1.2", colW * 0.4), h = 0.22"
圆角: rectRadius = 0.04"
填充: 纯色（按序号轮替：1A50D6 / 4E82C5 / 7CB3E0）
边框: 无 (line: {type:'none'})
文字: 8.5pt, 粗体, 白色 #FFFFFF, 水平居中+垂直居中
```

#### D. 内容描边框（圆角矩形）
```
形状: roundRect (圆角矩形)
位置: x = cardX, y = cardY + headerRowH + 0.05"
大小: w = colW, h = contentH
圆角: rectRadius = 0.08"
填充: 纯白 #FFFFFF
边框: color = E5EBF5(浅蓝灰), width = 1.0pt
阴影: 无（⚠ 区别于 cards 布局的弥散阴影）
```

#### E. 内容 Bullet 文字（描边框内）
```
文本框: x = cardX + 0.15", y = contentY + 0.1"
        w = colW - 0.30", h = contentH - 0.20"
内容: 每行 "· " + 文字（自动清除原有前缀后重加）
字号: 10pt, 常规, 颜色 #4E5969 (中灰)
行距: 1.35 倍
对齐: 左对齐, 垂直顶部对齐
```

#### F. footerBar 底部横条（可选）
```
形状: roundRect (圆角矩形)
位置: x = M(0.5"), y = 页面底部上方 ≈ 4.875"
大小: w = CW(9.0"), h = 0.35"
圆角: rectRadius = 0.05"
填充: 腾讯蓝 #1A50D6
文字: 9.5pt, 粗体, 白色, 水平居中+垂直居中
```

**完整渲染顺序（build_ppt.js 中）**：
1. 如有 `intro`，先渲染正文段 (A)，调整 startY
2. 计算网格位置（cols × rows）
3. 遍历 cards 数组，对每张卡片依次画：编号标题 (B) → 标签色块 (C) → 描边框 (D) → Bullet 文字 (E)
4. 如有 `footerBar`，在底部渲染蓝色横条 (F)

- 3 张独立圆角白卡（第三代橙色浅底 `#FFF0E0`+ 橙色描边）横向排列，中间 `→` 蓝色箭头连接
- 每张卡：左侧彩色竖条 + 圆形序号徽章 + "Generation One/Two/Three" 英文小字 + 中央大标题（代际名本身作为主视觉）+ 产品标签条 + bullets + 底部胶囊
- **末代主题色 = 橙色 `FF6A00`**（破例专用），前两代分别为腾讯蓝 `1A50D6` 和中蓝 `4E82C5`
- 标题区自渲染（skipCommonTitle=true）

**适用场景**：
- ✅ 产品代际演进（如 AI 工具三代、广告平台三代）
- ✅ 范式变革展示（传统 → 数字化 → 智能化）
- ✅ 方法论演进（1.0 → 2.0 → 3.0）
- ❌ 不适合超过 3 阶段的流程（用 `phases` 或 `formula_phases`）
- ❌ 不适合平级对比（用 `compare` 或 `table`）

**设计灵感**：基于哈哥 2026-04-21 定稿的 `slide_ai_evolution.png` 原型图，2026-04-22 沉淀为标准模板。

## 五、使用方法（5 步标准流程）

### Step 1: 需求理解 → 页面规划（🛑 检查点 1）

从用户需求出发，拆解为页面规划表：

```
| 页码 | 布局类型 | 主标题（草稿） | 核心内容 |
|------|---------|---------------|---------|
| 1    | summary | 三大核心能力... | 结论+3要点 |
| 2    | cards   | 门店营运提效... | 4张能力卡片 |
| 3    | phases  | 分三阶段落地... | 3阶段路径 |
```

**🛑 暂停：将页面规划表展示给用户，确认后再继续。**
- 用户可能调整页数、布局类型、标题措辞
- 不要自行假设页面结构直接开写

### Step 2: 填充 JSON 数据 → 预检校验（🛑 检查点 2）

按确认的规划，为每页填写 JSON 数据。填完后执行预检：

**必检项（生成前强制）**：
- [ ] 每页都有 `layout` 且值在 8 种之内
- [ ] 每页都有 `mainTitle` 且 ≤ 40 个中文字符
- [ ] cards/cards_outlined 的 `cards` 数组非空且 ≤ 8 张
- [ ] table 的 `columns` 和 `rows` 数量匹配
- [ ] compare 的 leftItems/rightItems 均非空
- [ ] phases 的 `phases` 数组恰好 3 项
- [ ] kpi 的 `metrics` 数组 1-6 项
- [ ] JSON 语法正确（`JSON.parse` 无报错）

**🛑 预检全部通过后，才进入生成步骤。**

### Step 3: 调用生成脚本

```bash
node ~/.workbuddy/skills/Tenchage-ppt/scripts/build_ppt.js <输入JSON路径> <输出PPTX路径>
```

如报错，参考「七、异常处理与 Fallback」章节处理。

### Step 4: QA 截图验证（**强制执行**）

```bash
python ~/.workbuddy/skills/Tenchage-ppt/scripts/qa_screenshot.py <PPTX路径> [输出目录]
```

逐页对照「六、QA 流程」中的检查清单。

### Step 5: 整体连贯性审查（🛑 检查点 3，多页 PPT 时必做）

多页 PPT 生成后，额外检查：
- [ ] 页码连续且格式统一（-1-、-2-、-3-...）
- [ ] 标题风格一致（都用结论性标题，不要混用疑问句/陈述句）
- [ ] 配色一致（未出现超出 1.6 配色体系的颜色）
- [ ] 逻辑递进合理（不是随机拼凑）
- [ ] 无重复内容（不同页的 cards 内容不要雷同）

## 七、异常处理与 Fallback

遇到以下情况时，按对应策略处理，不要卡住或跳过：

### 7.1 JSON 数据问题

| 异常 | 处理 |
|------|------|
| JSON 语法错误（缺逗号/括号） | 使用 `JSON.parse()` 预检，报错时指出具体行号，修复后重新生成 |
| 必填字段缺失（如 mainTitle、cards） | 在生成前逐页校验，缺失时提示用户补充，不要用空值硬生成 |
| layout 值不在 8 种之内 | 提示用户可选值列表，建议最接近的布局类型 |
| cards 数量为 0 | 跳过该页，提示"空卡片页已忽略" |
| cards 数量 > 8 | 截断为前 8 张，在页面底部添加 "+N more" 注释，并提示用户拆分为多页 |

### 7.2 build_ppt.js 运行异常

| 异常 | 处理 |
|------|------|
| `pptxgenjs` 模块未安装 | 先执行 `cd ~/.workbuddy/skills/Tenchage-ppt && npm install`，然后重试 |
| Node.js 版本不兼容 | 要求 Node.js ≥ 16，提示用户检查 `node -v` |
| 脚本报错退出 | 完整输出 stderr 内容，定位到具体页码和布局类型，修复 JSON 后重跑 |
| 输出文件路径无写入权限 | 改为输出到当前工作区目录，提示用户手动移动 |

### 7.3 QA 截图环境问题

| 异常 | 处理 |
|------|------|
| 非 Windows 系统（无 PowerPoint COM） | 改用 `libreoffice --headless --convert-to png` 命令行截图。如 LibreOffice 也不可用，使用 `pdf2image` + `python-pptx` 导出为 PDF 后截图 |
| PowerPoint 未安装 | 同上，使用 LibreOffice 或 PDF 方案 |
| COM 调用超时/挂起 | 设置 30 秒超时，超时后 kill 进程重试一次。仍失败则跳过截图，标注"QA 未完成，建议手动打开检查" |
| `win32com` 模块未安装 | 执行 `pip install pywin32` 后重试 |

### 7.4 内容溢出与布局异常

| 异常 | 处理 |
|------|------|
| 主标题超过 40 个中文字符 | 自动截断到 40 字 + "..."，并在 QA 时标记为"标题过长，建议精简" |
| 卡片内 desc 文字超出边框 | 缩小字号到 9pt（最小不低于 8pt），仍溢出则截断末尾加 "..." |
| table 列数 > 6 | 提示用户"表格列数过多可能导致文字挤压"，建议拆分或缩减列 |
| compare 单侧条目 > 8 | 截断为 8 条，提示用户精简 |
