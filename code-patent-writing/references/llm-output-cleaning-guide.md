# LLM 输出清洗规程（LLM Output Cleaning Guide）

本规程定义了专利文档的 LLM 输出清洗流程（7 层清洗管道）。当使用 LLM 生成专利内容后，**必须**按本规程逐层清洗，确保最终文档无 AI 工具痕迹。

---

## 清洗管道概览

```
原始 LLM 输出
  │
  ├─ Layer 1：对话前缀清除（89+ 种模式）
  │
  ├─ Layer 2：技能/工具名泄漏清除
  │
  ├─ Layer 3：代码块移除
  │
  ├─ Layer 4：Markdown 表格转自然语言
  │
  ├─ Layer 5：运行时错误标记清除
  │
  ├─ Layer 6：对话性垃圾清除
  │
  ├─ Layer 7：工程/JSON 产物清除
  │
  └─ 最终清洗：空行压缩 + 尾部分隔符清除
```

---

## Layer 1：对话前缀清除

**原理**：扫描文本头部，移除连续的对话性引导段落，直到遇到真正的内容标记（Markdown 标题、加粗文本、列表项、编号章节）。

### 需要清除的前缀模式（89+ 种）

**任务确认类**：
```
将按、将使用、将直接、本次我会、本次将
好的、好，、好!
以下是、下面是、下面我
让我、我会、我将、我来、我已
收到、明白、了解
我已确认、已确认
```

**用户引用类**：
```
根据你、按照你、根据您、按照您
你的需求、您的需求
理解了你的、理解了您的
那么接下来、接下来我
```

**工具调试类**：
```
`rg`、`rg` 不可用、我改用、改用 `find`
`find`、`sed`、`grep`、`cat`
无法使用、不可用，、工具不可用
先读取、先查看、先检查、先搜索
正在读取、正在查看、正在搜索、正在分析
读取完成、查看完成、搜索完成、分析完成
已完成读取、已完成查看、已完成搜索
```

**技能/任务泄漏类**：
```
本次任务是、本次我将
使用 `、使用`
技能处理、技能已读取、技能说明已读取、先快速读取、已读取
我先、我先读取
读取技能、参考技能
code-patent-writing、patent-writing
skill 、skill：
工具调用、函数调用
上下文已、文档已读取
```

### 内容标记（遇到即停止扫描）
```
##、**、- 、* 、1.、2.、3.、【
```

### 清除算法

从第一行开始逐行扫描：
1. 空行在前缀块内 → 标记为可删除
2. 以内容标记开头 → 停止扫描
3. 以前缀模式开头 → 标记为可删除，继续
4. 非空、非前缀、非标记 → 停止扫描

---

## Layer 2：技能/工具名泄漏清除

### 正则模式

1. 清除含技能/工具操作描述的整行：
   ```
   ^.*?(?:读取|查看|加载|使用).*?(?:技能|skill|说明|指引|上下文).*$
   ```

2. 清除反引号包裹的技能/工具名引用：
   ```
   `[a-z_-]+(?:skill|writing|patent|reading)[a-z_-]*`
   ```

---

## Layer 3：代码块移除

专利文档**不应包含任何代码块**。清除所有 fenced code blocks：

```
多行：```<lang>\n...\n``` → 删除
单行：```<lang> {...} ``` → 删除
```

---

## Layer 4：Markdown 表格转自然语言

**原理**：专利文档中不应出现 Markdown 表格格式，需转换为自然语言段落。

### 转换规则

检测连续的 `| ... | ... |` 行（≥3 行，含表头+分隔符+数据行）：

| 列数 | 转换格式 |
|------|---------|
| 1 列 | `**值**` |
| 2 列 | `**col1值**：col2值` |
| 3 列 | `**col1值**（col2值）：col3值` |
| 4+ 列 | `**col1值**（col2值）：col3值。col4值。...` |

不足 3 行的表格（非真正表格）保持原样。

---

## Layer 5：运行时错误标记清除

清除以下模式的整行：

```
[error] ...
[warning] ...
[tool_error] ...
[info] ...
RUNTIME: Resource not found
Error: ...
[error] RUNTIME: ...
tool_error
undefined
```

---

## Layer 6：对话性垃圾清除

### 文本任意位置的对话性语句（整行清除）

```
.*如果你需要.*
.*如果需要.*我可以.*
.*我可以继续.*
.*如果你希望.*
.*如果您需要.*
.*如果您希望.*
.*需要我继续.*
.*需要进一步.*请告诉.*
.*是否需要我.*
.*请告诉我是否.*
.*希望我.*展开.*
.*以上是.*的.*部分.*如有.*
.*以上内容涵盖了.*
```

### 工具调试痕迹（嵌入在正文中的）

```
.*`rg`\s*不可用.*
.*我改用\s*`\w+`.*
.*改用\s*`find`.*
.*`(?:rg|find|sed|grep|cat|awk)`.*(?:搜索|查找|替换|读取|不可用).*
.*(?:工具|命令)(?:不可用|不存在|报错).*
.*(?:正在|已完成)(?:读取|查看|搜索|分析).*(?:文件|目录|内容).*
.*技能(?:说明|文件|内容)已(?:读取|加载).*
.*(?:先快速|快速)读取.*(?:文件|内容|技能).*
```

---

## Layer 7：工程/JSON 产物清除

### 清除条件

对匹配以下模式的行，**仅当该行的 CJK 字符比例 < 30% 时**才清除（避免误删含少量工程词但主体是中文叙述的正文句子）：

```
含工程变量名：task_id、sla_ms、api_key、config.、.json、.yaml、.py、.ts
含 JSON 键值对："key": "value" 或 "key": 123
含内联 JSON 对象：{"key": ...}
```

### CJK 比例判断公式

```
cjk_ratio = CJK字符数 / 总字符数
if cjk_ratio < 0.3:
    删除该行（大概率是代码/JSON，不是自然语言）
else:
    保留（可能是含少量术语的正文）
```

---

## 最终清洗

1. **空行压缩**：连续 4+ 个空行压缩为 2 个
2. **尾部分隔符清除**：文末的 `---` 分隔符删除
3. **首尾空白清除**：`strip()`

---

## Ideal 文本注入前的消毒

当将 Ideal 文档（代码分析结果）注入到专利撰写 prompt 中时，需要先消毒以下标记：

| 标记模式 | 说明 | 处理 |
|---------|------|------|
| `[代码参考: xxx]` | 代码文件引用 | 删除 |
| `[ref: func_name]` | 函数引用标记 | 删除 |
| `[推断]` / `[估算]` / `[inferred]` | 推断标记 | 删除 |
| `[file: path/to/file.py, ...]` | 代码证据标记 | 删除 |
| `[N/A]` | 无数据标记 | 删除 |
| `` `_func_name()` `` | 裸露的代码函数名 | 删除 |

消毒后压缩连续空行，清除行尾空白。

## 使用说明

### 在智能体中使用

智能体生成专利章节后，应按以下顺序清洗：

1. 检查输出开头是否有对话前缀 → 删除
2. 搜索工具/技能名泄漏 → 删除
3. 检查是否有 ``` 代码块 → 删除
4. 检查是否有 Markdown 表格 → 转为自然语言
5. 搜索 AI 味高频词（参考 writing-style-guide.md）→ 替换
6. 搜索运行时错误标记 → 删除
7. 检查工程变量/JSON 残留（CJK < 30% 的行）→ 删除

### 在 orchestrate.py 中使用

`orchestrate.py` 的 `stage_docx()` 阶段会自动调用 `patent_to_json.py` 进行 Markdown 清洗。但如果直接在智能体中生成内容（不走 pipeline），则需要手动按上述步骤清洗。
