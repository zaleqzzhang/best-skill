# 发明专利技术交底书 - 模板格式说明

## 文档整体结构

交底书分为两大部分：**头部信息表格** 和 **正文章节**。

## 一、头部信息表格

4行表格，包含以下字段：

| 字段 | 是否必填 | 说明 |
|------|---------|------|
| 交底书名称 | 必填 | 即发明名称，简洁概括技术方案 |
| 交底书撰写人 | 必填 | 撰写人姓名 |
| 本发明涉及产品和技术 | 必填 | 涉及的产品名称和技术领域 |
| 竞对或竞品名称 | 选填 | 竞争对手或竞品 |
| 撰写人联络方式 | 选填 | 手机号/微信号 |
| 专利保护的目的 | 必填 | 多选：标准技术相关/维权目的相关/原创产品功能或技术/奖项申报专利相关/合同交付相关/功能或技术改进/其他 |

## 二、正文章节

**语言风格总要求**：写交底书时要像在给同事讲技术方案，用平实的工程语言，多用动词，少堆砌抽象名词。具体风格规范见 [writing-style-guide.md](writing-style-guide.md)。

### 1、【关键术语】
列出技术方案中的专业术语并给出明确定义。定义要具体，说清楚这个词在本方案里指的是什么，不要用另一个抽象词去解释抽象词。

### 2、【发明构思】（必填）
用1-3段话讲清楚：我们要解决什么问题？现有方案为什么不够好？我们的思路是什么？

**写作要点**：
- 先说痛点，再说思路，最后点明关键创新
- 不要用"本发明提供一种..."开头，直接讲问题和解决办法
- 让读者看完知道"原来是这么回事"

### 3、【背景技术】

#### 3.1 相关背景描述，以及现有技术的技术方案（必填）
描述与本发明最相近的现有技术方案，讲清楚别人是怎么做的。

**写作要点**：
- 按技术演进的脉络来讲，而不是并列罗列
- 每种方案要说清楚原理和局限，别只扔一个名字

#### 3.2 现有技术的缺点或尚未解决的问题，以及本专利技术方案可以解决的问题（必填）
分两部分写：
- A、现有技术的缺点或尚未解决的问题
- B、专利技术方案可以解决的问题

**写作要点**：
- 缺点要具体，不要只说"效率低"、"效果差"，说清楚差在哪里
- 本方案解决的问题要和前面的缺点对应上

### 4、【发明内容】（图文并茂）

#### 4.1 产品侧（必填）
从用户视角描述产品功能、交互流程、界面表现等，配合GUI截图或示意图。

**写作要点**：
- 按用户操作的流程来写，不要按系统模块来写
- 说清楚用户能看到什么、能做什么操作、系统会给什么反馈

#### 4.2 技术侧（必填）
从技术实现角度描述系统架构、处理流程、算法逻辑等。

**写作要点**：
- 不要只列步骤编号，每个步骤要说清楚"为什么要这么做"
- 把技术细节和设计意图串起来，让读者理解整个方案的推导逻辑
- 关键算法要讲清楚输入是什么、怎么处理、输出是什么
- 数据结构和存储方式要结合使用场景来讲

#### 4.3 专利方案所产生的有益效果（必填）
结合4.2技术侧的具体方案，说明技术效果，可辅以实验数据。

**写作要点**：
- 效果要可验证，最好有数据支撑
- 不要只说"提高了效率"，要说"在XX场景下，处理时间从XX秒降到XX秒"
- 每个效果都要能追溯到具体的技术手段

### 5、参考文献
列出相关专利、论文、网页、期刊等参考资料。

## 三、撰写要求

1. 必填项必须完整填写
2. 产品侧需附应用场景图和GUI交互图
3. 技术侧需附流程图或时序图
4. 技术方案应清楚完整，包含技术细节
5. 有益效果不能凭空臆断，要结合技术方案分析
6. 优选提供2-3个扩展方案或不同应用场景
7. **语言风格**：遵循 [writing-style-guide.md](writing-style-guide.md) 中的规范，避免模板化表述
